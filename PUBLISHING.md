# Publishing this feed

The site under `docs/` is generated by `wp publish` from the workspace at
`../wirepost-wptest`. Nothing here is written by hand.

## The one hazard worth knowing

**`git add docs/*` silently omits `.well-known/`.** Shell globs do not match
dot-entries, so the handle descriptor is generated correctly by every build,
never staged, and never deployed. The feed publishes and verifies perfectly; only
`@name@domain` resolution quietly does not work. That is exactly what happened
here, and it is invisible from the published feed.

Stage with an explicit `-A` and a pathspec, which does match dot-entries:

```sh
git add -A -- docs
```

## Publish

```sh
cd ../wirepost-wptest
wp publish                       # builds, deploys to ../wptest/docs, verifies
cd ../wptest
git add -A -- docs
git status --short               # confirm .well-known/ is staged when it changed
git commit -m "Publish"
git push
```

## Check it before trusting it

```sh
curl -sI https://withlowe.github.io/wptest/.well-known/wirepost.json | head -1
```

`wp publish` runs the same check itself when `web` is set in `wirepost.json`, and
a missing descriptor is **fatal** — but only against what is *deployed*. Between
`wp publish` and `git push`, the local tree and the live site disagree, and this
file exists because that gap is where the descriptor was lost.

Do not add a `.gitignore` that ignores dotfiles. `.nojekyll` and `.well-known/`
both have to ship.
